1. Scope

Vanvas provides moderation, security, server management, logging, community features, levels, virtual coins and music on Discord. This policy explains the information processed by those features. Some information is processed automatically when the bot is present; other information depends on commands and settings chosen by server administrators or users.

2. Information processed and stored

  • Discord identifiers and profile information: user, server, channel, role and message IDs; usernames, display names and avatars used to respond to commands and display notices. The bot also uses server membership, roles, permissions and relevant Discord event information.
  • Message processing: messages accessible to the bot are processed for prefix commands, security filters, autoresponders, activity counts and other enabled features. The bot does not keep a general database archive of every message. However, message text can be retained or copied by the features described below.
  • Moderation and security records: member and moderator IDs, case numbers, action, reason, time, warning records and applicable durations; security settings, exemptions and trusted-user lists.
  • Logging: when configured, the bot posts deleted/edited message excerpts, attachment links, member and invite activity, voice joins/leaves/moves, and channel, role and permission changes to Discord log channels. Security logs can include the message that triggered a filter. Access depends on the server's Discord permissions.
  • Recent deleted and edited messages: the bot keeps the latest deleted/edited message per channel in memory, including the author and message text. Moderators can retrieve it through snipe commands for up to 10 minutes. That access limit is not an automatic memory-erasure timer; entries can remain until replaced or the process restarts.
  • Tickets and modmail: ticket metadata includes the opener, server, channel and ticket number. Closing a ticket can produce a transcript of up to 1,000 messages, including authors, times, message text, selected embed text and attachment links, sent to the configured Discord ticket log. Modmail forwards DMs and up to three attachments to a server's staff thread and relays staff replies to the user. Thread-to-user mappings are stored. Closing modmail archives the Discord thread; it does not erase the conversation.
  • User-submitted content: reminders, AFK reasons, suggestions and staff responses, application answers and status, confession text, poll questions/options/votes, and configuration text such as custom commands, autoresponders, welcome messages and named embeds can be stored. Confessions retain the submitter's user ID: they are not anonymous to the operator, and an administrator command can reveal the author. Deleting a posted confession marks its record deleted but does not erase its stored text and author ID.
  • Invites: inviter and invited member IDs, invite code, join time, leave time, rejoin status, counts, bonus adjustments and invite reward settings. Attribution is best-effort and may be unknown.
  • Levels, games and virtual economy: user IDs, XP/levels, message counts, balances, cooldowns, streaks, wins/losses, inventory and related settings. Some records are per server; virtual-coin wallets and some cooldowns are keyed by user ID across servers. Virtual coins are game data, not payment-card information.
  • Other feature settings: role assignments and saved roles, verification, panels, giveaway entries, temporary channels/roles, scheduled messages and optional birthday day/month information.
  • Activity analytics: message counts by server, channel, hour/day and user, plus join/leave totals. These analytics tables store counts, not message content.
  • Server-structure backups: snapshots contain role names, colors, permissions and positions; category/channel names, structure and role permission overrides; and applicable topics, slowmode, NSFW, voice limits and related channel settings. These feature backups do not include member lists or message histories.

3. Music and external requests

Music requests are resolved using YouTube through yt-dlp. Requested song names or links are sent to the source service; lyric lookups send search terms such as the track and artist to LRCLIB. Audio passes through the hosting server for playback. The current playback path streams audio through memory and a decoder rather than maintaining a permanent music library. Music queue and requester information is held in process memory.

No active AI or language-model processing was found in the deployed code. The current AI extension does nothing. A legacy AI settings table remains in the database; it was empty when reviewed.

4. Storage and access

The bot stores feature records in a SQLite database on its Waifly hosting server. It also keeps runtime caches and diagnostic console output. Discord holds the messages, logs, transcripts, attachments and staff threads the bot posts there.

The operator can access bot storage. Server administrators and people with the relevant Discord permissions can access their server's logs, transcripts and other feature output. Waifly, Discord and music/lyrics services process information needed to provide their services under their own terms and policies. No advertising-data sale or advertiser integration was found in the reviewed bot code. This does not mean that no information is disclosed to service providers or server staff.

Do not send passwords, payment details or other secrets to the bot. Its free-text features can retain information that users choose to submit.

5. Retention

There is no single automatic retention period for all bot data. - Most persistent feature records remain until removed by an applicable command or manually by the operator. Removing the bot from a server does not automatically erase that server's database records. - Message-count and per-user activity analytics older than 60 days are pruned during analytics flushes. Join/leave aggregates do not have the same automatic 60-day deletion in the reviewed code. - Server-structure backups retain the newest five snapshots per server. Older snapshots are removed when another backup is saved; admins can also delete saved snapshots. - Some temporary records are removed when their task completes or expires, such as delivered reminders and expired temporary-ban records. This does not erase related Discord messages or moderation history. - Runtime caches ordinarily disappear on process restart, subject to the snipe caveat above. - Discord logs, transcripts and forwarded messages remain until deleted in Discord. Disabling a feature does not automatically remove its previous output.

6. Controls, access and deletion requests

Server administrators can configure or disable supported features, change log destinations and remove the bot. Some records have feature-specific removal commands, such as birthday removal or backup deletion. There is no unified self-service command to export or erase all personal data.

Contact @swapnendu0390 or the support server to request access, correction or deletion. Include your Discord user ID and the affected server ID if known, but do not send secrets. Requests require manual review and may require identity or server-authority verification. This policy does not promise a fixed response time or automatic deletion that the software does not implement. For copies in server logs or staff threads, contact that server's administrators as well. Any request remains subject to applicable law.

7. Age and updates

Use the bot only if you meet Discord's applicable minimum-age requirements. This policy should be reviewed when the bot's data practices change. The published version should state its effective date.
